# 决策记录

本文件从 2026-11-15 起记录产品与协作决策。此前各阶段的方案写在对应分支的 README 里，这里不补写或改写那些历史决定。

## 2026-11-15 管理控制台改版方向与协作边界

**决定**

- 管理控制台这一轮先做界面改版，做成标准后台：左侧一列导航切页，右侧展示内容。登录页独立，登录后再进入这套布局。
- 导航分组已定：管理端为「租户与 Key」「模板」；租户端为「资产」「任务」「Webhook」「用量与配额」。当前页要高亮。右侧页头要能看出当前管理员和已选用的租户上下文，但不展示 Key 明文。
- 现有管理功能和租户功能都保留，不因改版丢失（上传与续传、取消 / 重试 / 重转、试播、Key 明文只显示一次等）。
- 未登录、未选 Key、Key 过期或失效时，页面给出明确说明和正确入口，不要把接口返回的 `unauthorized（401）` 当作主要提示。前端引导不能绕过服务端权限。
- 不改后端接口、鉴权与数据模型，不改旧「短剧场」播放页，不在本轮扩展 OAuth、完整 RBAC 或新业务。
- 本轮在 `plan/console-redesign` 只提交需求文档（README 分支方案和本决策记录）。界面视觉方案由 Fable 出，Frank 拍板；开发仍由 Frank 自行驱动 Claude 在该分支进行。没有 Frank 的明确指令，不自动启动设计或开发。
- 配色、字体家族、是否使用现成 UI 组件库等视觉与技术选型，Frank 尚未选定，不能写成已批准。

**原因**

- 检查现有控制台时，入口挤在顶部一行，看起来简陋；管理员登录后进入资产页，权限模型（管理登录与租户 Key 分开）没有被界面讲清楚，容易直接看到 401。
- Frank 明确要求先把后台整理成标准的左右布局，并按既有流程从 `main` 开分支、把需求写进该分支 README，而不是只在聊天里贴一段说明。
- 视觉方案交给 Fable，避免在需求里擅自指定配色或组件库；实现仍按既有分工，需求文档不写业务代码、不写技术设计，也不在这一步直接委派设计或开发。

**排除**

- 不把这一轮做成功能扩展或后端改造。
- 不把只出现在聊天里的说明当成已经落盘的需求。
- 不把未拍板的配色、UI 库或实现架构写成既定方案。

**未定**

- 配色、字体家族、圆角和装饰风格。
- 是否引入现成 UI 组件库、用哪一套。
- 侧栏在窄屏上的具体收纳方式。
- 「短剧场」入口在控制台里的具体位置。
- 除已定侧栏分组以外的其他视觉细节。
